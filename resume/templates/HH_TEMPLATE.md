# Методичка: как составить резюме для HH.ru

Как устроено сильное резюме на HeadHunter (формат актуален для СНГ). Ниже —
структура, шаблон каждого блока, правила форматирования и на чём делать акцент.
Заполняй по образцам-заготовкам: `[в скобках]` — то, что подставляешь под себя.

---

## 1. Общая структура

Резюме линейное, сверху вниз, в фиксированном порядке блоков HH:

1. **Шапка** — ФИО, фото, демография, контакты, локация, релокация.
2. **Желаемая должность и зарплата** — таргет-позиция, тип и формат занятости.
3. **Опыт работы** — обратный хронологический порядок (свежее сверху). HH сам
   считает суммарный стаж и выводит его заголовком.
4. **Образование** — уровень, год, вуз, специальность.
5. **Навыки** — знание языков + облако тегов-технологий.
6. **Дополнительная информация («Обо мне»)** — soft skills, активности, дубль контактов.

**Ключевая особенность вёрстки HH — двухколоночная сетка** внутри блоков опыта и
образования: узкая левая колонка = мета (даты, длительность, уровень), широкая
правая = содержание. Рекрутёр сканирует таймлайн слева, не читая тело.

**Объём:** у HH нет западного лимита в 1 страницу. 1–2 страницы на джуна/мидла,
2–3 на сеньора — норма СНГ.

## 2. Шаблон блоков

### Шапка
```
[Фамилия Имя Отчество]
[Пол], [возраст], родился [дата рождения]
[+7 (___) _______] — предпочитаемый способ связи
[email]
telegram: [@ник]
Мой GitHub: [ссылка]
Проживает: [город]
Гражданство: [страна], есть разрешение на работу: [страна]
Готов к переезду: [города] / готов к командировкам
```
- **Фото** — деловое/нейтральное, светлый фон. Для СНГ его наличие повышает отклик;
  отсутствие читается настороженно.
- **Демография** (пол, возраст, дата рождения) — стандартна для HH, не убирается.
- **Один контакт помечай «предпочитаемый способ связи»** — снижает трение рекрутёру.
- **GitHub / портфолио — в шапку.** Для разработчика это сигнал «есть что показать».
- **Релокация и командировки** расширяют воронку — HH матчит вакансии по этому полю.

### Желаемая должность и зарплата
```
[Точное название вакансии]
Специализации: [из списка HH]
Тип занятости: [полная / частичная / проектная]
Формат работы: [удалённо / гибрид / офис]
Зарплата: [вилка, ₽]
```
- **Заголовок = точное название целевой вакансии**, а не «IT-специалист». По нему HH
  ранжирует резюме в поиске рекрутёра — это главное ключевое слово.
- Тип и формат занятости открывай по максимуму → больше совпадений.
- **Указывай зарплатную вилку.** Пустое поле = «по договорённости»: допустимо, но
  конкретная вилка поднимает отклик и отсекает нерелевантные звонки.

### Опыт работы — ядро резюме

Каждая позиция строится по одному шаблону:

| Левая колонка | Правая колонка |
|---|---|
| Период (Месяц ГГГГ — Месяц ГГГГ) | **Название компании** (жирным) |
| Длительность (авто) | Город, сайт компании |
| | Должность |
| | 1 строка — что за продукт / зона ответственности |
| | **Обязанности:** маркированный список |
| | **Достижения:** маркированный список с метриками |

Заготовка одной позиции:
```
[Месяц ГГГГ] — [Месяц ГГГГ]        [Название компании]
                                    [Город, сайт]
                                    [Должность]
[Одна строка: что за продукт, домен, масштаб.]

Обязанности:
* [Роль/процесс: что делал регулярно — стек, методология, зона ответственности.]
* [...]

Достижения:
* [Глагол] + [что сделал] + [измеримый эффект: с X до Y / устранил / ускорил].
* [...]
```

**Разделение «Обязанности / Достижения» — самый важный приём.**
Обязанности отвечают на «что ты делал» (роль, стек, процессы), достижения — на «что
изменилось благодаря тебе» (результат + метрика). Рекрутёр читает достижения первыми.

### Образование
```
[Уровень: Магистр/Бакалавр/...] · [год] · [вуз, город] · [специальность]
```
- Профильность **не обязательна.** Если образование непрофильное (свитчер) — опыт и
  навыки перевешивают. Блок заполняется тем, что есть.

### Навыки
- **Языки:** формат HH `[Язык] — [уровень]` (напр. Родной / B1 — Средний).
- **Облако тегов** — плоский список всех технологий стека. Это ключевые слова для
  поиска рекрутёра и HH-фильтров: пихается весь стек, включая пересекающиеся варианты
  (напр. `HTML` и `HTML5`). Сюда — фреймворки, языки, инструменты, практики (Code Review,
  CI/CD).

### Дополнительная информация («Обо мне»)
- Soft skills и активности, которым не место в блоке опыта: менторинг, доклады/митапы,
  участие в адаптации новичков, профессиональные интересы, работа с AI-инструментами.
- В конце **продублируй контакты** (ТГ, тел, GitHub) — чтобы рекрутёр не листал наверх.

## 3. Форматирование — правила

- **Обратный хронологический порядок** во всех блоках (свежее сверху).
- **Даты** строго `Месяц ГГГГ — Месяц ГГГГ`; длительность считает HH.
- **Маркеры списков** короткие, по строке; вложенность — отступом.
- **Жирным** — только названия компаний и вуза. Никакого цвета и иконок: HH-экспорт
  монохромный и строгий.
- **Служебные заголовки блоков** («Опыт работы», «Навыки») генерит HH — не трогай.
- **Единый шаблон для каждой позиции** — рекрутёр читает пятое место работы так же
  быстро, как первое.

## 4. На чём делать акцент

1. **Достижения важнее обязанностей.** Обязанности = контекст, достижения = ценность.
   Всегда разделяй эти два списка.
2. **Метрики в достижениях.** Каждое достижение по формуле
   **[глагол действия] + [что сделал] + [измеримый эффект]**:
   - «сократил время загрузки с ~[X]с до ~[Y]с»
   - «сократив количество шагов с [N] до [M]»
   - «устранив [конкретную проблему]»
   Начинай с глагола: *провёл, переработал, оптимизировал, внедрил, реализовал, настроил*.
3. **Сквозная специализация.** Пусть через всё резюме проходит один явный «конёк»
   (напр. производительность, отказоустойчивость, работа с данными) — это делает
   профиль запоминающимся.
4. **Ключевые слова стека — везде:** в обязанностях, достижениях и в облаке навыков.
   Дублирование намеренное: и человек, и HH-поиск, и ATS находят нужные технологии.
5. **Каждая позиция начинается с 1 строки о продукте** — рекрутёр понимает домен и
   масштаб до того, как нырять в детали.
6. **Целевой заголовок = название вакансии** — главный фактор попадания в поиск.
7. **Soft skills и активности — в самом конце** («Обо мне»), не размывают опыт.
8. **Актуальность стека** — упоминание свежих инструментов и практик показывает, что
   кандидат не застрял в технологиях пятилетней давности.

---

## 5. Чек-лист

- [ ] Целевой заголовок = точное название вакансии.
- [ ] Указана зарплатная вилка.
- [ ] Фото деловое, контакты + один «предпочитаемый», GitHub/портфолио в шапке.
- [ ] Каждое место работы: 1 строка о продукте → **Обязанности** → **Достижения**.
- [ ] В каждом достижении — метрика или конкретный устранённый эффект.
- [ ] Достижения начинаются с глагола прошедшего времени.
- [ ] Облако навыков = весь стек ключевыми словами (для HH-поиска).
- [ ] Один сквозной акцент-специализация через всё резюме.
- [ ] Soft skills и активности — в «Обо мне», не в опыте.
- [ ] Обратный хронологический порядок, единый шаблон для всех позиций.

---

**Главный вывод:** резюме на HH работает за счёт двух вещей — жёсткого разделения
«Обязанности / Достижения» и того, что **каждое достижение измеримо**. Всё остальное
(шапка, навыки, образование) — стандартный контейнер HH; конкурентное преимущество
создаётся именно в блоке достижений.
